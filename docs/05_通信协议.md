# 通信协议

## 1. 数据流分层

本教具故意使用两种不同接口：

- Pico 到电脑：USB CDC 上的紧凑二进制协议，保留 2 kS/s 原始 ADC 数据和 CRC。
- 电脑到机器人：TCP 上的 UTF-8 NDJSON，只发送 20 Hz 状态摘要和触摸事件，便于不同语言接入。

不要把 Pico 的 2 kS/s 原始点逐条变成 JSON 再发送给机器人。机器人通常需要的是已经解释过的状态和事件，原始波形仍由上位机记录和显示。

## 2. USB CDC 说明

Raspberry Pi Pico 使用原生 USB CDC，不是 RP2040 UART 经 USB 转换。因此：

- 操作系统仍会把设备显示成 COM 口；
- 上位机可向串口 API 填写 115200 作为兼容占位；
- 实际 USB 传输速率不由 115200、8N1 控制；
- 真实采样节拍必须以 `HELLO.sample_rate_hz` 和 `SAMPLE.sample_period_us` 为准。

## 3. 二进制帧 v1

所有多字节整数均为小端序。一个完整帧由固定 18 字节头、变长 payload 和 2 字节 CRC 组成。

| 偏移 | 长度 | 字段 | v1 含义 |
| ---: | ---: | --- | --- |
| 0 | 2 | `magic` | 固定字节 `0x4C 0x53`，ASCII `LS`。 |
| 2 | 1 | `version` | 固定为 1。 |
| 3 | 1 | `type` | 消息类型。 |
| 4 | 2 | `payload_len` | payload 字节数，v1 发送给 Pico 时不得超过 128。 |
| 6 | 4 | `sequence` | 发送方向内独立递增的无符号序号，允许 `0xFFFFFFFF→0` 回绕。 |
| 10 | 8 | `timestamp_us` | 发送方单调微秒时间；SAMPLE 中表示本批首样本时刻。 |
| 18 | N | `payload` | 由消息类型决定。 |
| 18+N | 2 | `crc16` | 小端 CRC16-CCITT-FALSE。 |

CRC 参数固定为：

| 参数 | 值 |
| --- | --- |
| 名称 | CRC-16/CCITT-FALSE |
| 多项式 | `0x1021` |
| 初值 | `0xFFFF` |
| 输入/输出反射 | 否 / 否 |
| `xorout` | `0x0000` |
| 覆盖范围 | 从 `magic` 第一个字节到 payload 最后一个字节，包含完整 header，不包含末尾 CRC 字段。 |

接收端必须能处理半帧、粘包、魔数前噪声、超长长度和错误 CRC。坏帧后应从下一字节继续搜索 `4C 53`，不能通过关闭再打开串口来代替流式重同步。

### 3.1 CRC 互操作测试向量

序号为 1、时间戳为 0、空 payload 的 START 帧，在添加 CRC 前是：

```text
4C 53 01 03 00 00 01 00 00 00 00 00 00 00 00 00 00 00
```

CRC 数值应为 `0xA0AB`；因为线上为小端，完整帧末尾是 `AB A0`：

```text
4C 53 01 03 00 00 01 00 00 00 00 00 00 00 00 00 00 00 AB A0
```

## 4. 消息类型

| 类型值 | 名称 | 方向 | 用途 |
| ---: | --- | --- | --- |
| `0x01` | `HELLO` | 双向 | Pico 报告能力；电脑可发送空 payload 请求重新报告。 |
| `0x02` | `SAMPLE_BATCH` | Pico → 电脑 | 发送一批等间隔 ADC 样本。 |
| `0x03` | `START` | 电脑 → Pico | 清空旧缓冲并开始一条新的采样流。 |
| `0x04` | `STOP` | 电脑 → Pico | 停止采样并清空缓冲。 |
| `0x05` | `ACK` | Pico → 电脑 | 确认已处理的控制命令。 |
| `0x06` | `ERROR` | Pico → 电脑 | 报告协议、长度或命令错误。 |

电脑和 Pico 各自维护自己的发送序号。Pico 发出的 HELLO、SAMPLE、ACK 和 ERROR 共用同一条 Pico→电脑序号；电脑不能假定两个 SAMPLE 之间一定只相差 1，而应考虑期间是否收到其他合法类型。

## 5. HELLO payload

HELLO 固定为 16 字节。

| payload 偏移 | 类型 | 字段 | 当前值/含义 |
| ---: | --- | --- | --- |
| 0 | `u16` | `sample_rate_hz` | 2000。 |
| 2 | `u8` | `batch_samples` | 20。 |
| 3 | `u8` | `adc_bits` | 12。 |
| 4 | `u16` | `adc_max` | 4095。 |
| 6 | `u16` | `ref_mv` | 3300。 |
| 8 | `u8` | `adc_channel` | 0，表示 GP26/ADC0。 |
| 9 | `u8` | `fw_major` | 固件主版本。 |
| 10 | `u8` | `fw_minor` | 固件次版本。 |
| 11 | `u8` | `fw_patch` | 固件修订版本。 |
| 12 | `u32` | `capabilities` | 当前默认 `0x00000007`。 |

`capabilities` 位定义：

- bit 0：支持 START/STOP 流控制；
- bit 1：SAMPLE 包含 PVA103 摆幅和缓冲溢出 flags；
- bit 2：header 时间戳是批次首样本的单调微秒时间；
- 其他位保留，接收端必须忽略未知置位，不能因此拒绝设备。

## 6. SAMPLE_BATCH payload

当前正常 payload 长度为 44 字节。

| payload 偏移 | 类型 | 字段 | 当前值/含义 |
| ---: | --- | --- | --- |
| 0 | `u16` | `sample_period_us` | 500，即 2 kS/s。 |
| 2 | `u8` | `sample_count` | 20。 |
| 3 | `u8` | `flags` | 本批硬件状态。 |
| 4 | `u16[sample_count]` | `samples` | 20 个 0–4095 原始 ADC 值。 |

`flags` 位定义：

- bit 0：本批至少一个样本 `<= 931`，约等于 PVA103 OUT `<= 0.75 V`，接近低端摆幅边界；
- bit 1：本批至少一个样本 `>= 3165`，约等于 OUT `>= 2.55 V`，接近高端摆幅边界；
- bit 2：自上一批以来，采样环形缓冲曾溢出；
- bit 3–7：保留，接收端忽略。

阈值按 PVA103 的有效输出摆幅设置，不能改回 ADC 的 0/4095。PVA103 可能早在约 0.7–2.6 V 形成平台，ADC 本身尚未到电源轨。

ADC 电压换算为：

`voltage_v = adc_raw × ref_mv / 1000 / adc_max`

这表示 PVA103 输出端/ADC 输入端电压，不等于未经前端影响的“PVDF 开路电压”。

## 7. 控制、ACK 和 ERROR

### 7.1 START/STOP

START 和 STOP 的 payload 必须为空。电脑方向的 `sequence` 独立递增；Pico 在 ACK 中原样回显命令类型和命令序号。

### 7.2 ACK payload

ACK 固定为 5 字节：

| 偏移 | 类型 | 字段 | 含义 |
| ---: | --- | --- | --- |
| 0 | `u8` | `acked_type` | 被确认的命令类型。 |
| 1 | `u32` | `acked_sequence` | 被确认的电脑方向命令序号。 |

### 7.3 ERROR payload

| 偏移 | 类型 | 字段 | 含义 |
| ---: | --- | --- | --- |
| 0 | `u16` | `code` | 固件错误码。 |
| 2 | `u8` | `related_type` | 导致错误的命令类型。 |
| 3 | `u32` | `related_sequence` | 相关命令序号。 |
| 7 | `u8` | `text_len` | 后续 UTF-8 文本字节数。 |
| 8 | `u8[text_len]` | `text` | 便于日志显示的 UTF-8 说明。 |

固定错误码如下；主机应优先按数字码处理，`text` 只用于人类阅读：

| code | 名称 | 含义 |
| ---: | --- | --- |
| 1 | `BadCrc` | 收到的主机帧 CRC16 不匹配。 |
| 2 | `MalformedFrame` | 协议版本、长度或帧格式无效。 |
| 3 | `UnsupportedMessage` | 主机发送了 v1 中不允许的消息方向或类型。 |
| 4 | `InvalidPayload` | HELLO、START 或 STOP 带了非空 payload。 |
| 5 | `SamplingUnavailable` | 500 µs 采样定时器初始化失败，固件拒绝 START。 |

## 8. Pico 状态机

1. USB CDC DTR 建立后，Pico 保持停止状态并主动发送一次 HELLO，不自动采样。
2. 电脑发送空 payload START；Pico 清空旧环形缓冲、开始采样并 ACK。
3. 重复 START 是合法操作：Pico 重启一条干净采样流并 ACK。
4. 电脑发送 STOP；Pico 立即停止、清空缓冲并 ACK。
5. 重复 STOP 是幂等操作，仍返回 ACK。
6. 电脑发送空 payload HELLO 请求时，Pico 先回复 HELLO，再返回 ACK。
7. USB 断开后 Pico 自动停止采样、清缓冲并重置命令解析器。

## 9. 机器人 TCP NDJSON v1

默认机器人服务器监听 `127.0.0.1:18080`。上位机作为 TCP 客户端，以 UTF-8 发送“一行一个 JSON 对象”，每行以 `\n` 结束。JSON 内容本身不得包含未转义换行。

公共字段如下：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema` | string | 固定 `pvdf.touch.v1`。 |
| `version` | integer | 固定 1。 |
| `type` | string | `telemetry`、`event_start` 或 `event_end`。 |
| `message_id` | integer | 从 1 递增的消息标识，在本次上位机运行内唯一，用于 ACK 匹配。 |
| `sequence` | integer | 最近处理的 Pico/模拟批次序号。 |
| `time` | string | 带时区的 ISO 8601 主机时间。 |
| `device_time_us` | integer | 最近样本的设备单调微秒时间。 |
| `adc_raw` | integer | 最近 12 位 ADC 值。 |
| `voltage_v` | number | ADC 输入电压。 |
| `baseline_v` | number | 当前基线电压。 |
| `delta_voltage_v` | number | 相对基线变化电压。 |
| `envelope_v` | number | 动态包络。 |
| `touch_intensity_pct` | number | 0–100 的相对动态触摸强度。 |
| `touch_state` | string | `dynamic_change` 或 `idle`。 |
| `level` | string | `无`、`轻触`、`中触` 或 `重触`。 |
| `saturated` | boolean | 当前批次是否接近 PVA103 摆幅边界。 |

`telemetry` 以 20 Hz 发送，用于机器人侧连续反馈或界面显示。`event_start` 和 `event_end` 在事件变化时立即发送，并额外包含：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `event_id` | integer | 同一次开始/结束共用的事件编号。 |
| `peak_delta_voltage_v` | number | 该事件截至当前的最大变化电压绝对值。 |
| `peak_intensity_pct` | number | 该事件峰值相对强度。 |
| `duration_ms` | number | 开始事件为 0；结束事件为完整持续时间。 |

默认接口不包含 `force_n`。只有完成带参考测力计的动态力标定并携带 `calibration_id` 时，扩展版本才可以加入估算力字段。

## 10. 机器人 ACK

机器人接收每条消息后返回一行 UTF-8 JSON：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `schema` | string | 固定 `pvdf.ack.v1`。 |
| `version` | integer | 固定 1。 |
| `type` | string | 固定 `ack`。 |
| `ack_message_id` | integer/null | 原消息的 `message_id`；无法解析原消息时为 null。 |
| `ack_sequence` | integer/null | 原消息的 `sequence`；无法解析原消息时为 null。 |
| `accepted` | boolean | 是否接受该数据。 |
| `robot_time` | string | 带时区的机器人接收时间。 |
| `action` | string | 接受时默认 `data_received`，拒绝时为 `rejected`；真实适配器只能返回白名单动作名。 |
| `detail` | string | 简短结果或拒绝原因。 |

上位机用发送时间到匹配 ACK 的时间计算 ACK 延迟。机器人接收器应以 `message_id` 去重。断线期间，上位机仍在本地显示并记录触摸事件，但不把这些事件排入网络待发送队列；重连后只发送新事件，不补发已经过期的机器人动作。

本机模拟接收器把单条 NDJSON 消息限制为 1 MiB；超过限制时关闭当前客户端连接。正常 telemetry 或事件远小于该上限，真实机器人适配器也应设置类似的输入长度限制。

## 11. 机器人适配安全

- `telemetry` 可以驱动灯光亮度、表情或可视化，不应直接映射到无限制关节命令。
- `event_start/event_end` 只能选择预先配置的动作白名单。
- 未收到 ACK 不能显示“机器人已执行”，只能显示“已发送/未确认”。
- 连接恢复后只处理新消息，不能把断线期间积压的触摸事件重放给实体机器人。
- 实体机器人输出应默认关闭，并由人工显式使能。
