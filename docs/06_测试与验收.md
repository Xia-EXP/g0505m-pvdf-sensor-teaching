# 测试与验收

## 1. 验收原则

验收必须覆盖真实数据路径：传感器机械结构、PVA103、Pico ADC、USB CDC、上位机处理、TCP JSON、机器人 ACK。只运行软件单元测试不能证明整套教具可用。

“按住后持续显示压力”不属于 LDT0-028K 单传感器方案的验收项。若项目提出这一要求，应判定传感器选型不满足，并增加静态力传感器。

## 2. 硬件验收

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| H-01 | 断电核对逐针接线 | PVA103 由 Pico 3V3 供电；OUT 经 2.2 kΩ 到 GP26；100 nF 在 ADC 侧对地；TTL 不接；VBUS 不接。 |
| H-02 | 测 PVA103 供电 | `VCC-GND` 为约 3.3 V，无异常发热。 |
| H-03 | 静置查看 OUT/ADC | 输出位于有效范围内，不长期贴近约 0.75 V 或 2.55 V 警戒边界。 |
| H-04 | 连做 10 次最大正常触摸 | 波形没有平顶/平底，SAMPLE bit0/bit1 不出现。 |
| H-05 | 检查结构 | 膜片无孔、无尖折，活动区不被硬夹，导线有应力释放，重触不会撞硬底。 |
| H-06 | 静置 60 秒 | 没有持续误触；若有明显 50 Hz 波纹，应先整改布线或屏蔽。 |

## 3. 固件和 USB 协议验收

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| P-01 | 建立 USB CDC DTR | Pico 主动发 1 个合法 HELLO，并保持未采样。 |
| P-02 | 检查 HELLO | 2,000 Hz、20 点、12 位、4095、3,300 mV、ADC0、capabilities `0x7` 与固件版本正确。 |
| P-03 | 发送 START | 收到匹配类型和命令序号的 ACK；随后每约 10 ms 收到 20 点 SAMPLE。 |
| P-04 | 检查 SAMPLE | `period_us=500`、`count=20`、payload 44 字节、时间戳代表首样本。 |
| P-05 | 检查 30 分钟序列 | 合法帧 CRC 错误为 0；无无法解释的序号缺口；flags.bit2 始终为 0。 |
| P-06 | 注入半帧、粘包和前导噪声 | 解析器正确等待或重同步，不崩溃、不输出伪样本。 |
| P-07 | 篡改一个数据字节 | CRC 错误帧被拒绝，紧随其后的合法帧仍能恢复。 |
| P-08 | 发送超长 payload_len | 固件拒绝并能继续接收下一合法命令。 |
| P-09 | 重复 START/STOP | START 重开干净数据流；STOP 幂等；每条命令都收到匹配 ACK。 |
| P-10 | 拔掉 USB 后重连 | Pico 自动停止并清缓冲；重连后重新 HELLO，不泄漏旧半帧或旧样本。 |

CRC 实现必须通过 [通信协议](05_通信协议.md) 中的 START 已知测试向量。

## 4. 信号处理验收

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| S-01 | 启动后前 2 秒保持静止 | 完成前不产生触摸事件；完成后基线稳定。 |
| S-02 | 做 5 次轻触和 5 次重触标定 | 标定完成；重触参考明显大于轻触参考；顺序颠倒时明确拒绝、保留旧值并提示重做。 |
| S-03 | 各做 10 次轻、中、重触 | 三组峰值中位数依次增加；重触不削顶。 |
| S-04 | 单次触摸带自然振铃 | 一次主要触摸不被振铃拆成大量重复事件。 |
| S-05 | 按住 2 秒 | 开始时有动态响应，保持时回落，松开可能有反向响应；界面不宣称持续压力。 |
| S-06 | 缓慢温漂或轻微零点变化 | 空闲基线缓慢跟随，触摸峰值不被立即吸收到基线。 |
| S-07 | 用夹具或固定手法重复同一动作 20 次 | 变化电压峰值相对中位数的最大偏差目标为 ±15%；超出时先检查触摸位置、机械松动和削顶，不能直接用软件缩放掩盖。 |

建议统计验收：同一操作者在固定触摸点的轻触和重触各 10 次，重触峰值中位数至少比轻触高 20%，且两组不能因前端削顶集中在同一个上限。该比例用于检查演示可分辨性，不是 LDT0-028K 的通用精度规格。

## 5. 上位机验收

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| U-01 | 在无硬件时启动模拟数据 | 可看到 2 kS/s 合成 PVDF 波形，并可触发轻、中、重模拟触摸。 |
| U-02 | 选择 Pico 或指定 COM | 能开始/停止、自动处理 USB 断线并给出中文状态，不冻结 UI。 |
| U-03 | 查看实时界面 | 同时显示 ADC、电压、基线、变化电压、包络、动态强度、等级和削顶状态。 |
| U-04 | 查看协议/JSON 区域 | 可看到当前帧或机器人消息，字段与协议文档一致。 |
| U-05 | 记录一次课程 | 生成逐点 CSV 和事件/机器人 JSONL；字段和时间轴足以回放。 |
| U-06 | 回放刚才的 CSV | 无需 Pico 即可重放原始 ADC 波形并重新运行当前算法；原始事件结果以同目录 JSONL 为准。若要复算出相同事件，必须使用相同机械结构、标定参数，且 CSV 开头包含至少 2 秒静置基线。 |
| U-07 | 连续运行 30 分钟 | 无崩溃或持续内存增长；曲线仍流畅；USB 丢帧和缓冲溢出均为 0。 |

实时显示不要求 2,000 FPS。合理目标是采样完整保持 2 kS/s、曲线刷新不低于 25 FPS，同时让 UI 操作保持响应。

## 6. 机器人链路验收

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| R-01 | 启动本机机器人模拟器 | 上位机连接 `127.0.0.1:18080`，连接状态清楚可见。 |
| R-02 | 静置 10 秒 | 模拟器以约 20 Hz 收到 telemetry，JSON 每行可独立解析。 |
| R-03 | 完成一次触摸 | `event_start` 和 `event_end` 使用同一 `event_id`，并分别立即发送。 |
| R-04 | 检查 ACK | `ack_message_id` 和 `ack_sequence` 匹配原消息；界面显示真实 ACK 延迟。 |
| R-05 | 比较 JSON 与 UI | ADC、电压、动态强度、等级和削顶状态一致。 |
| R-06 | 停止模拟器后触摸 | 本地波形和事件记录继续工作，但断线事件不进入网络待发送队列；界面不能把它显示成已执行。 |
| R-07 | 恢复模拟器 | 只处理恢复后的新消息，不重放断线期间已经本地记录的旧触摸动作。 |
| R-08 | 重复相同 `message_id` | 机器人接收端去重，不重复执行实体动作。 |

从触摸事件被上位机识别并进入网络发送队列，到收到本机机器人 ACK 的延迟，目标 P95 小于 100 ms。它包含线程排队、TCP 发送和 ACK 返回时间，但不包含人体开始施力到算法越过阈值之前的物理时间。

## 7. 教学内容验收

由一名未参与开发的教师按课堂脚本演示，满足以下条件：

- 能在 15 分钟内完整展示传感器、采样、协议、算法和机器人 ACK；
- 能明确解释“动态触摸强度”与“静态压力”的区别；
- 学生能从界面追踪一次触摸经过的每个数据阶段；
- 断开机器人不会影响本地采集，且能区分“已发送”和“已确认”；
- 无需安装开发环境即可运行发布版上位机和模拟器。
