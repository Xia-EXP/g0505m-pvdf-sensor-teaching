# GT-G0505M 手掌受力教具 2.0.0

本项目使用厂家串口版采集器直接提供的25路压阻式估算值，单位g。适合观察位置、轻重变化与持续抓握过程。25个点的数值合计不等于完整整手握力；未覆盖区域不生成虚构压力。

## 首次使用

1. 在Windows 10 1809及更新版本或Windows 11上完整解压便携包，双击 `启动G0505M教具.cmd` 或 `G0505MTeaching.exe`。保留同目录的 `_internal`，无需安装Python或Qt。
2. 按本文件夹的厂家真实接线插图，核对采集器与USB-TTL转换器：TX→RX，RX→TX，GND共地。确认厂家5V供电方式与转换器UART电平兼容。不要按陌生线色接线，不要重复接入两路5V电源。
3. 在设备管理器确认转换器串口；选择对应端口后点击“连接”。本机当前转换器为COM3/CH340，另一台电脑的编号可能不同。
4. 即使没有按压，也应收到周期上报帧。等待状态且接收字节为0表示没有数据到电脑，不等于受力为0，也不能据此判断传感器损坏。
5. 收到有效帧后选左/右手；逐点轻按确认编号。点选位置查看该点当前值、峰值和最近20秒曲线。

CH340驱动是操作系统与硬件的边界：便携包不静默安装驱动。若没有串口，安装转换器厂家提供的驱动，或由学校管理员处理。程序不会自动修改采集器型号、上报周期或左右手标识。

## 2.0.0 新功能

顶栏新增页面切换“实时 / 实验 / 分析 / 标定”和“课堂 / 研究”模式。课堂模式只显示实时与实验页，按钮少、字大；研究模式增加分析、标定页和“明细表”。切换页面不会中断采集、记录或正在进行的实验。快捷键（空格、Z、P、←/→）只在实时页生效。

- **强脑 Revo2 三维手**：实时页右侧显示 BrainCo Revo2 灵巧手模型（Apache-2.0，来源见 `_internal/grip_teaching/assets/revo2/NOTICE.md`）。零件按受力着色，25 个点的位置画出受力标记，可拖动旋转。**手指弯曲由受力推算，仅示意，不是实测关节角**；软件不连接、不控制真实机械手。电脑不支持 OpenGL 时自动改用 2D 示意手。
- **数据网格**：实时页“数据”标签按“手指列 × 指段行（指尖/上段/下段/根部）+ 掌部行”排列 25 个数值，等宽右对齐、按色标着色，底部显示接触点数、最大点、主要用力区域和所选点峰值。
- **引导实验**（实验页）：逐点核对、轻重对比、持续抓握与回零、不同物体抓握。大字提示每一步，按阈值和时长自动判定完成；第一步松手后自动空载归零。每次实验自动记录到 `文档\G0505M实验数据\日期_实验名\`，结束后写入 `experiment.json` 结论。某点无法完成可点“跳过此步”。示例数据下可以演示流程，但结论注明不能作为实物证据。
- **数据分析**（研究模式）：打开一份或多份 `channels.csv` 叠加比较；按 40 g 开始 / 20 g 结束自动切分按压，列出峰值、达峰时间、保持均值、保持漂移率、松手残留；统计重复性 CV；显示全程峰值热图。保持段不足 0.5 秒时不评价漂移，下一次按压在松手后 1.5 秒内开始时不评价残留（显示 `--`）。可导出指标 CSV 和截图。
- **已知载荷标定**（研究模式）：选手和感应点，填写压头直径和砝码序列（必须含 0 g），按提示逐级加载、卸载；放好后等 3 秒稳定再取 2 秒均值，波动过大要求重测。拟合给出斜率、截距、R²、最大误差、迟滞和重复性（2 轮以上），保存到 `文档\G0505M标定\`。点“在实时页启用”后，实时页可选“标定当量”。

标定边界：必须先登记量程，载荷不得超过量程的 80%（软件拒绝）；用与感应点同尺寸的平底刚性压头垂直居中加载，手按不是标定；只能使用串口实物数据。标定结果称“标定当量 g”，只对该压头面积和加载方式有效，不代表整手握力，不换算为牛顿或帕斯卡；未标定的点仍显示厂家值，CSV 始终保存厂家原始值。

## 1.1.0 界面速览

- 深色投影界面。圆点颜色由暗到红表示该点估算值相对“色标上限”的大小；外圈弧长是当前值占比，白点是峰值；新按下的点会出现扩散圆环。
- 十字准星是25个测点按正值加权的“受力中心”，拖尾显示最近1.6秒的移动。它只反映采样点分布，不是整手合力作用点。
- 右侧“哪里用力最多”按五指和掌部汇总正值占比，只比较分布，不代表握力大小。
- 没有数据时，手掌中央直接提示下一步。串口有数据但25点持续8秒全为0时，角落会提示检查按压位置和排线。
- 量程、色标、参数查询收在“设置”中。快捷键：空格冻结，Z归零，P清峰值，←/→换点，F11全屏。
- “示例”按“全手抓握 → 两指捏取 → 掌心下压”循环播放，仍标注为非实物数据。

## 观察与处理

- 初始显示厂家原始值，不做自动归零、平滑或截断。
- “空载归零”需先释放物体，并确认当前手没有接触载荷；以当前有效帧为固定零点，重开曲线和峰值区间。抓握时零点保持不变。归零后显示允许负值，便于观察零点偏差和漂移。
- “冻结”只冻结画面，采集与记录继续；解除后显示最新值。冻结时不能归零和复位峰值。
- “复位峰值”以当前值作为新起点，仅影响当前手。
- “色标上限”只改变颜色饱和范围。数值超过色标上限仍完整显示和记录。
- 量程初始“未确认”。只读查询识别到明确型号后登记2/5/10kg每点版本，未知回复保持未确认，也可以按订单手动登记。登记不会发送 `SETF`。参数查询按钮只发送 `SET=?\r\n`，同时保留原字节供核对。
- 该手超过1秒没有新帧标为“数据过期”，保留最后值；断开亦保留最后值。只有新的有效校验帧可以恢复更新。左右手分别保存零点和峰值。
- “示例”是合成数据，标题与会话明确标注，不能作为实物测量证据。停止后仍保留“示例数据”来源标记。

## 记录与回放

点击“记录”选择保存目录，程序创建新的时间命名文件夹。结束时点击“停止记录”，或关闭程序自动保存。

| 文件 | 内容 |
|---|---|
| `channels.csv` | 电脑接收Unix纳秒时间、L/R、25路原始g及25路固定零点g，UTF-8 BOM可供Excel读取 |
| `valid_frames.bin` | 校验成功的厂家53字节帧，按接收顺序拼接 |
| `received_bytes.bin` | 记录期间全部串口接收字节，包括噪声、坏帧和查询回复 |
| `session.json` | 来源、115200 8N1、量程登记、色标、开始/结束解析计数、归零和其他操作事件 |

记录期间约每50帧刷新一次文件缓冲。磁盘故障会明确报错并停止记录。软件计数是实际有效帧与校验错误，不含虚构“精确丢帧数”：厂家协议没有设备序号和设备时间戳。

回放选择 `channels.csv`，支持播放/暂停、0.5/1/2倍速、进度拖动以及原始/归零后切换。保留同目录的 `session.json`，以恢复来源和量程；缺少该文件时来源标为未核对。拖动进度后曲线及峰值从目标前最近20秒观察区间重新统计。一次最多100万帧。回放期间不能给原记录重新归零。

## 课堂安排

| 实验 | 做法 | 观察结论 |
|---|---|---|
| 逐点按压 | 轻按1～25号，观察对应点变化 | 检查空间编号、左右手与镜像是否一致 |
| 同点轻重 | 对同一点连续轻按、较重按，避免尖锐接触 | 比较该位置估算值和峰值，不能直接称精确测力 |
| 持续抓握 | 软球抓握5秒再释放，期间不归零 | 观察保持期间的变化、迟滞和漂移 |
| 不同物体 | 软球、海绵、圆滑握柄分别重复3次 | 比较接触点分布；手姿、接触面积和材料都会改变读数 |

用教师演示引入，学生记录“哪个点、最大值、保持时变化、释放后是否回到原值”，再对比三次。不要以点值合计排名学生握力，不用尖锐物体、猛烈挤压或拉扯排线。

## 资料结论和边界

厂家资料：<https://hcn2yloo448w.feishu.cn/wiki/EsALwFJ3timvKGkic4ZcXth9nvg>

采用压阻阵列，25点，可持续观察受力。串口版最快20ms/帧；厂家标注重复性±8%、迟滞＜6%、漂移＜8%，这些参数不是全条件准确度承诺。精确计量需用固定夹具、已知载荷、规定接触面积和姿态分别验证。

厂家示例帧53字节、校验0x8E，通道高字节在前。协议位于厂家5.1节，编号参照2.5节；真实串口接线插图参照3.6节。`assets/manufacturer-*.png`为厂家公开文档截图，归原作者所有，仅用于配套教学核对。实际收到的接线照片尚未提供，不能据此声称用户已正确接线。

2026年10月11日用户重新安装并修正错接线后，COM3实测15.047秒收到300个有效帧，校验错误0，全部是右手帧；首次检查首尾25路均为0。只读查询返回 `type:G0505M_5kg`、`Set time:50 ms`、`Right Hand!`、固件 `V.2026-8-7M-r5`，因此本机实物为5kg每点版本，当前上报约20帧/秒。查询还显示全局零值20g、零点死区3g，这些是设备固件内部设置，桌面没有修改。

此前“打开COM3但没有任何字节”的问题已随修正接线恢复。已有有效帧并不等于25点安装位置、按压响应、标定精度均已验收；需继续按下方步骤核对。详细实测证据保存在 `release/G0505M实物接收检查_*`，长时间运行证据位于 `release/G0505M30分钟实物记录_*`。

本次长时检查进程运行1800.063秒，但原录制在约1659.850秒（27分40秒）后停止，保存33,222个有效帧、校验错误0，25路全为0。后段出现解析计数重置及数据过期，原因未核实，因此连续30分钟验收仍待完成。最终报告的2,785帧只对应结束时的新解析器，不能冒充全程统计。详见 `验证结果.md` 和 `soak_latest.json` 的 `recording_audit`。

## 源码与构建

保留原 `pvdf_teaching`。新代码位于 `desktop/src/grip_teaching`，两个程序的硬件模型和协议互不替换。

| 模块 | 中文作用 |
|---|---|
| `models.py` | 25空间通道、左右手与电脑时间模型 |
| `protocol.py` | 帧头、手标识、高字节在前与和校验，逐字节重同步 |
| `parameters.py` | 只读参数文本识别，保存型号、周期与厂家内部零点信息 |
| `sources.py` | 后台115200 8N1读取、指定端口重连和只读查询 |
| `processing.py` | 每手固定归零、原始/净值峰值、20秒历史 |
| `recording.py` | CSV、有效帧、全接收字节、会话JSON及严格回放读取 |
| `controller.py` | 数据源代号过滤、过期判断、会话记录与播放时钟 |
| `hand_view.py` | 厂家编号空间布局、左右镜像、测点着色及命中选择 |
| `ui.py` | 中文仪表界面、点选、冻结、归零、记录和回放控件 |
| `fonts.py` | 读取Windows本机字体，兼容离屏截图，不分发系统字体 |
| `app.py` | 正式启动与便携软件启动检查入口 |

源码版使用Python 3.12，运行依赖见 `desktop/requirements.txt`。在desktop目录：

```powershell
py -3.12 -m venv .venv-build
.venv-build\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv-build\Scripts\python.exe -m pip install -e .
.venv-build\Scripts\python.exe run_g0505m.py
```

构建：`powershell -ExecutionPolicy Bypass -File desktop/build_g0505m.ps1 -InstallDependencies`。源码交付包包含独立项目元数据、中文解释、针对新教具的测试、构建脚本与配套资料。便携EXE由PyInstaller生成，运行不需要这套开发环境。

## 验收

软件检查已覆盖厂家例帧、52种拆包边界、粘包、噪声、校验错误、左右手、固定归零、记录回放、旧连接回调、模拟拔插、冻结继续记录和磁盘错误。真实Qt截图检查1366×768和1024×720。测试与示例运行不能证明真实传感器接受度。

实物待完成：25点逐点核对；左右镜像；按住/释放/归零；真实USB拔插重连；夹具与已知载荷定量验证。30分钟运行结果见单独的实测记录；本机量程已由只读参数确认是5kg每点，换采集器后应重新查询。

30分钟实物测试：使用确认正确的接线，以串口实时模式开始记录，保持操作并轮流轻按感应点；结束保存起止时间、CSV帧数、校验错误差值、接收字节差值、是否出现过期及界面响应。记录开始时计数已有值，要用session.json开始/结束计数的差值。还应记录空载和已知载荷前后漂移。没有真实帧时验收结果应为“待完成”。
